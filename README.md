# Slap Battles Arena Bot

Модульный проект автономного боевого бота для Slap Battles.

## Текущее состояние

Версия **0.1.1 — каркас проекта**. Реализованы загрузка модулей, окно состояния,
перетаскивание и завершение сессии. Повторный запуск завершает предыдущую сессию.
Наблюдение, принятие решений, движение, бой, восстановление и память — явно
обозначенные заготовки. Автоматическая игра пока не реализована.

## Запуск

Для клиентской среды, предоставляющей `loadstring` и `game:HttpGet`:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/Probothotspot/Slap-Battles-Arena-Bot/main/loader.lua"))()
```

В обычном Roblox LocalScript такой способ исполнения недоступен. В этой версии
открываются окно загрузки и диагностическое окно приложения. В рабочем сервере
Roblox интерфейс и поведение каркаса ещё не проверены.

### Диагностика загрузки

Окно в `loader.lua` появляется до скачивания остальных модулей. Счётчик **0–17**
отражает 13 загрузок модулей и 4 проверки: среда, манифест, интерфейсы и запуск.
README, ROADMAP и .gitignore не исполняются как Lua.

- Видны этап, прогресс, предупреждения и конкретные ошибки.
- Проверяются скачивание, компиляция, выполнение и возвращаемый тип файлов,
  обязательные методы модулей и размеры UI.
- `Ready = false` показывается как заготовка, а не готовая боевая система.
- После ошибки файла проверка остальных продолжается, запуск блокируется.
- Зависимые проверки помечаются пропущенными. 17/17 означает завершение проверки;
  результат показывают отдельные счётчики ошибок и предупреждений.
- Ожидание скачивания и выполнения с уступкой планировщику ограничено 20 секундами.
  Это не защита от бесконечного цикла без уступки планировщику.
- После запуска показываются доступные ошибки проекта из LogService. Сообщения
  могут отсутствовать или обрезаться; это не полная проверка игрового поведения.
- Закрытие окна во время загрузки отменяет запуск. После загрузки закрывается
  только диагностика. Закрытие основного окна завершает сессию и диагностику.
- Ошибка скачивания или синтаксиса самого `loader.lua` возникает раньше создания
  окна и остаётся доступна в консоли среды запуска.

## Файлы

| Путь | Назначение |
| --- | --- |
| `loader.lua` | Окно загрузки 0–17, диагностика и кеш модулей одной сессии |
| `manifest.lua` | Версия, точка входа и список систем |
| `main.lua` | Сборка модулей и жизненный цикл приложения |

| `Gui.lua` | Интерфейс и управление окном |
| `Perception.lua` | Наблюдение за противниками и ареной |
| `Decision.lua` | Оценка и выбор действий |
| `Navigation.lua` | Передвижение, обход препятствий и края |
| `Combat.lua` | Удары и способности |
| `Recovery.lua` | Смерть, респавн и восстановление состояния |
| `Memory.lua` | История наблюдений за противниками |
| `SlapBattles.lua` | Проверенная интеграция с конкретной игрой |
| `ROADMAP.md` | Очерёдность разработки |

## Исходные наработки

В репозитории [Slap-battles-Teleport](https://github.com/Probothotspot/Slap-battles-Teleport)
уже существуют `Bot SB (недоработанный)`, `Navigation-BOT.lua` и `Slap nearby`.
Они не копируются и не запускаются автоматически. Перед переносом проверяем
их реальные зависимости и совместимость с интерфейсами нового проекта.

Новые версии сначала проверяют текущие файлы репозитория, затем обновляют
нужный модуль. Изменения из ветки `main` подхватываются при следующем запуске;
уже работающая сессия автоматически не обновляется.
